# Step 4: Push + PR + Merge

For **single-ticket mode**: push the per-issue branch, open a PR, merge.

For **loop mode**: Step 3.7 already did push + PR creation (batch PR).
This step just merges.

`_lib.md` helpers used here: `issue_title`, `issue_to_item_id`,
`set_item_status`.

## Single-ticket mode

1. **Push**:
   ```bash
   git push -u origin "$BRANCH"
   ```

2. **PR** — `Closes #${ISSUE_NUM}` to auto-close the issue + auto-fire
   the project board's "Item closed → Done" workflow (if enabled). If
   the board's auto-workflow is off, Step 5 will move the status
   explicitly.

   ```bash
   T_TITLE=$(issue_title "$ISSUE_NUM")
   PR_BODY="## Summary

Closes #${ISSUE_NUM}: ${T_TITLE}

<extracted from the commit body + 문제 정의>

## Test plan
- [x] \`pnpm typecheck\` passed
- [x] \`pnpm lint\` passed
- [x] Local smoke against \`pnpm dev\` (per Step 5)
- [x] Each 성공 기준 from issue body PASS per its 통과 기준

🤖 Generated by /b-start ${ISSUE_NUM}"

   PR_URL=$(gh pr create --base main --head "$BRANCH" \
     --title "<commit-subject>" \
     --body "$PR_BODY")
   PR_NUMBER=$(echo "$PR_URL" | grep -oE '/pull/[0-9]+' | grep -oE '[0-9]+')
   ```

3. **Merge** — squash, delete remote branch:
   ```bash
   gh pr merge "$PR_NUMBER" --squash --delete-branch
   ```

   appee currently has no required reviewers / branch protection on
   main, so `--squash --delete-branch` works directly. If branch
   protection ever gets added, fall back to `--auto`.

## Loop mode (batch)

Step 3.7 already produced `$BATCH_PR_NUMBER` (batch PR body uses one
`Closes #N` line per issue — see b-start.md Step 3.7). Just merge:

```bash
gh pr merge "$BATCH_PR_NUMBER" --squash --delete-branch
```

> The batch PR's `Closes #A`, `Closes #B`, `Closes #C` lines each
> auto-close their respective issues on merge. Step 5 reconciles the
> board status afterwards (idempotent — safe if auto-workflow already
> moved them).

## After-merge: move board to "In review"

For every issue merged in this step, flip board status to **In review**:

- Single-ticket mode: just `$ISSUE_NUM`
- Loop mode: every issue number in `BATCH_ISSUES`

```bash
move_to_in_review() {
  local issue_num="$1"
  local item_id
  item_id=$(issue_to_item_id "$issue_num")
  [ -n "$item_id" ] && set_item_status "$item_id" "$STATUS_IN_REVIEW"
}

if [ -z "$BATCH_BRANCH" ]; then
  move_to_in_review "$ISSUE_NUM"
else
  for entry in "${BATCH_ISSUES[@]}"; do
    NUM=$(echo "$entry" | cut -d'|' -f1)
    move_to_in_review "$NUM"
  done
fi
```

> **Note**: GitHub Issues are closed by the `Closes #N` in the merged
> PR body. The board status move to `In review` is a *transitional*
> state — Step 5 verifies on origin/main and then moves to `Done`. If
> Step 5 fails, the outer retry loop reverts the merge; this lets the
> next attempt see the item in In review (not Done) so the verification
> gate is honored.

## Verify the merge landed

The merge commit must show up on origin/main before Step 5 verifies. The
merge commit SHA is captured by `b-start.md`'s outer retry loop:

```bash
git fetch origin main
MERGE_COMMIT_SHA=$(git rev-parse origin/main)
echo "MERGE_COMMIT_SHA=$MERGE_COMMIT_SHA"

# Sanity: the merge commit's subject should mention the issue/batch
git log -1 --pretty=%s origin/main | head -c 100
```

→ Continue to Step 5.
